# نموذج العمل والتسعير — شبكة comm.ly

> وثيقة تأسيسية: ما يبيعه المنافسون فعلاً، أين الفجوة، خططنا وأسعارنا، وكيف تُبنى المنصة تجارياً وتقنياً.
> المصادر: صفحات الأسعار الرسمية (أدوب، بتلي، لينكتري، شورت.آي أو، ريبراندلي) — بتاريخ أكتوبر 2026.

---

## 0. تحديث معماري معتمد (بعد قرار العلامة)

- **العلامة الأساسية للمشروع أصبحت `comm.ly`** (نطاق مملوك، صالح حتى 2028) — هي الاسم التجاري والموقع الأساسي: المنتج، الأسعار، الحساب، لوحة التحكم، API، الصفحات القانونية.
- النطاقات الأخرى (`3/4/6/7/8/9.com.ly` وأي نطاق يُضاف لاحقاً) تصبح **محركات تابعة للشبكة**، تعمل بنفس المحرك وDB الواحد، ولهذه المحركات هويات ومحتوى وأدوات مستقلة وتشير إلى `comm.ly`.
- الميزة: **يمكن إضافة/حذف/استبدال أي نطاق دون أي تأثير على الموقع الأساسي**، ودون تغيير الكود — فقط إضافة سطر في `sites/registry.mjs` ومشروع Pages جديد.
- هذا يحلّ قلق «الثقة» في النطاقات الفرعية: العلامة التجارية على نطاق أساسي قصير (`comm.ly`)، والمحركات بنية تحتية موزّعة وليست العلامة.

## 1. الملخص التنفيذي

اختصار الروابط "خبز السوبرماركت" كما وصفت: سلعة أساسية رخيصة تجلب الزوار، لكن الربح يأتي مما يُباع بجانبها: **النطاق المخصص، التحليلات، أكواد QR، صفحات البايو، الفِرَق، API، والعلامة البيضاء**.

كل المنافسين الكبار يفعلون ذلك بالضبط:
- **Bitly** لم تعد شركة "اختصار روابط"؛ تبيع QR وأكواد 2D ومحطات تحليلات وبطاقات أعمال رقمية وخططًا مؤسسية.
- **Dub** تعرّف نفسها كـ«بنية تحتية لبرامج الشركاء والعمولة» وتبيع Links + Partners بخطط تصل إلى 300$ شهرياً.
- **Linktree** تبيع "توحيد البصمة وتحصيل الأموال" للمبدعين: إزالة العلامة، الثيمات، التحليلات، الاشتراكات.
- **Short.io / Rebrandly** تبيعان العلامة البيضاء والنطاقات المخصصة والاستهداف الجغرافي والتكاملات.

**قرارنا:** نبدأ بمنتج قصير روابط ممتاز وسخي مجاناً (لجلب الزوار والسيو)، ونبيع 4 حزم واضحة: أفراد (Pro)، أعمال (Business)، وكالات (Agency/White-label)، ومؤسسات (Enterprise). نضغط السعر **أقل من الجميع بنسبة 40–80%** مع جودة أعلى في العربية ودعم محلي، وبوابة دفع مرنة (كريبتو + بطاقات عالمية) تُربط لاحقاً عبر منصة جاهزة.

## 4. الفجوة في السوق (لماذا قد ننجح)

1. **العربية أولاً**: منتج ولوحة تحكم ودعم بالعربية، مع RTL أصلي — لا منافس كبير يفعل ذلك بجدية.
2. **ليبيا والمغرب العربي**: بوابات الدفع العالمية صعبة هناك؛ التسعير الإقليمي + الدفع بالكريبتو + الدعم المحلي ميزة كبيرة.
3. **الاستمرارية/الاحتياطي**: 6 نطاقات تعني أن حجب نطاق في بلد لا يوقف الخدمة — قيمة حقيقية في أسواق الحجب.
4. **سعر أدنى**: خطة Pro بسعر 4$ مقابل 9–30$ عند الآخرين، مع مزايا لا يقدمونها بالعربية.
5. **الأدوات المجانية للسيو**: كل نطاق يستضيف أداة مجانية مختلفة (UTM، QR، فحص روابط، API playground، صفحات بايو) → زيارة من جوجل → تسجيل → ترقية.

## 6. اقتصاديات الوحدة (هل النموذج يعيش؟)

| البند | التكلفة |
|---|---|
| Cloudflare Pages + Functions + D1 + KV | 0$ حتى حدود سخية، ثم خطة Workers Paid **5$/شهر** |
| تخزين الوسائط R2 | 0$ حتى 10GB (ثم ~0.015$/GB) |
| البريد (Resend) | 0$ حتى 3,000 رسالة/شهر |
| النطاقات الستة | تجديد سنوي (تحقق من رسوم .com.ly) |
| **التعادل** | **2 مشترك Pro فقط يغطيان خطة Cloudflare المدفوعة** |

**قاعدة حماية المجاني:** لا نسجل نقرة-بنقرة لمستخدمي المجاني إلى ما لا نهاية. نستخدم تجميعاً يومياً (D1) + كاش KV، ونحتفظ بالسجلات الكاملة للخطط المدفوعة. هذا يحافظ على بقاء التكلفة قريبة من الصفر ريثما ينمو الإيراد.

**سيناريو 12 شهراً (متحفظ):**
- 3,000 مستخدم مجاني → 2% تحويل = 60 مشتركاً.
- 45 × Pro (4$) + 12 × Business (12$) + 3 × Agency (39$) = 180 + 144 + 117 = **441$/شهر** (~5,300$/سنة).
- التكلفة ~20–40$/شهر → هامش > 90%.

## 7. استراتيجية النطاقات الستة (نفس المنتج + أدوات مختلفة للسيو)

كل النطاقات تعمل على **نفس المحرك ونفس قاعدة البيانات**، لكن كل نطاق له هوية ومحتوى وأداة مجانية رئيسية تستهدف كتلة كلمات مفتاحية مختلفة — فيصبح لدينا 6 فرص ظهور في جوجل بدل واحدة، بلا محتوى مكرر:

| النطاق | الجمهور | الأداة المجانية (مغناطيس سيو) | الكلمات المستهدفة (أمثلة) |
|---|---|---|---|
| **3.com.ly** | عام/عربي | اختصار روابط + QR | اختصار روابط، تقصير رابط، رابط مختصر |
| **4.com.ly** | مسوّقون | منشئ UTM + روابط حملات | UTM builder, رابط تتبع حملة |
| **6.com.ly** | شركات صغيرة | اختصار جماعي (CSV) ودليل روابط | اختصار روابط للشركات، إدارة روابط |
| **7.com.ly** | مطورون | API Playground + أدوات مطورين (EN أولاً) | URL shortener API, link API |
| **8.com.ly** | دولي/إنجليزي | فاحص أمان الروابط + مُوسّع URL | link checker, expand URL, safe link |
| **9.com.ly** | مبدعون | منشئ صفحة بايو مجانية | link in bio, صفحة روابط |

> الربط التبادلي بين الستة (تذييل + صفحة شبكة + مقالات مشتركة بتوقيع كل نطاق) يبني "سلطة مجمّعة" طبيعية، بشرط ألا يكون المحتوى نسخاً — وإلا عاقبه جوجل كشبكة أبواب (Doorway).

### اللغة: عربي أساسي + إنجليزي
- **العربية في الجذر** `/` (السوق الأكبر فرصةً والأقل منافسة)، والإنجليزية على `/en/` مع `hreflang`.
- استثناء مدروس: النطاق 7 و8 قد يكونان **إنجليزي أولاً** لاستهداف المطورين والسوق العالمي، مع نسخة عربية.
- لا تكرر نفس المحتوى بين النطاقات بنفس اللغة: كل نطاق محتواه مختلف جوهرياً (نبرة، أمثلة، جمهور، مقالات).
- العربية ميزة تنافسية: Bitly/Dub/Linktree لا يقدمون تجربة عربية أصيلة ولا دعم عربي.

## 8. الإجابات المعمارية (كيف تُبنى الصفحات وتُخزَّن الأشياء)

### أ) الصفحات العامة: تُولَّد آلياً من المستودع
- المحتوى في المستودع بصيغة بيانات (`.json` / Markdown) داخل `content/<site>/`.
- سكربت بناء واحد `npm run build` ينتج `dist/<site>/` صفحات HTML ثابتة (عربي + إنجليزي).
- GitHub Actions تنشر تلقائياً إلى Cloudflare Pages عند كل push.
- إضافة محتوى لاحقاً = إضافة ملف بيانات/مقال، لا كتابة HTML يدوياً.
- عند الحاجة لتحرير من المتصفح بدون كود: نركّب **Pages CMS / Decap CMS** (مجاني) ليحرر المحتوى مباشرة ويحفظها في المستودع.

### ب) البيانات الديناميكية والتخزين
| النوع | المكان |
|---|---|
| الروابط والنقرات (مجمّعة يومياً) | **D1** |
| المستخدمون، الجلسات، الاشتراكات، الفواتير، API keys | **D1** |
| كاش التحويل + الحد من الإساءة | **KV** |
| الصور، QR، صور OG | **R2** (10GB مجاناً) أو أصول في المستودع |
| المحتوى الثابت، الهوية، النصوص | المستودع (Git) |
| الأسرار (مفاتيح، توكنات) | Cloudflare Secrets — لا تُرفع للمستودع |

### ج) تسجيل الدخول والحسابات
- `POST /api/auth/register` و`/api/auth/login` عبر Pages Functions.
- كلمات المرور تُخزَّن مشفّرة بـ **PBKDF2 (Web Crypto)** — لا نص صريح أبداً.
- جلسات في D1 + كوكي `HttpOnly; Secure; SameSite=Lax`.
- رابط سحري بالبريد (Resend مجاناً) كخيار دخول بلا كلمة مرور.
- OAuth (Google/GitHub) لاحقاً للمطورين.
- `/app` لوحة العميل، `/admin` لوحة الإدارة (دور مستقل).
- حدود الخطة تُفرض في Middleware واحد يقرأ الجلسة + جدول الاشتراك.

### د) الاشتراكات والدفع (جاهز للمنصة التي ستُربط لاحقاً)
- جدول `subscriptions` (plan, status, period_end, provider, external_id).
- نقطة واحدة `POST /api/billing/webhook` مع تحقق توقيع — تقبل أي مزوّد.
- صفحة أسعار + صفحة "إتمام الشراء" تُحوّل إلى بوابة الدفع (استضافة/redirect).
- **Adapter** لكل مزوّد: كريبتو، بطاقات، تحويلات — دون تغيير المحرك.
- تحديث الخطة تلقائياً على `payment.succeeded` / `subscription.cancelled`.

### هـ) النطاقات: 6 مشاريع Pages من مستودع واحد
- كل نطاق = مشروع Cloudflare Pages مستقل، مع `SITE_ID` مختلف في البناء → محتوى/هوية مختلفة من نفس الكود.
- إضافة الدومين: Cloudflare → Pages → Custom domains (شهادة SSL تلقائية). النطاقات أصلاً على Cloudflare (ian/nancy) فلا حاجة لتغيير المسجل.
- لا نستخدم "صفحة واحدة بلا محتوى مختلف" لكل النطاقات: Google يعتبر ذلك محتوى مكرراً/شبكة أبواب ولا يمنح السلطة المطلوبة. ستة محتويات فريدة هي الطريق.

## 10. مؤشرات النجاح (KPIs)
- زوار شهريون لكل نطاق (هدف 6 أشهر: 10 آلاف مجمّع).
- نسبة التسجيل من الزائر (هدف ≥ 4%).
- تحويل المجاني → المدفوع (هدف 2–3%).
- الإيراد المتكرر الشهري (MRR) وتعافي التكلفة.
- معدل بقاء المشتركين (هدف > 85% سنوياً).
- زمن التحويل (p95) < 60ms، وتوافر > 99.9%.
