# الخطة الكاملة — شبكة comm.ly لاختصار الروابط

> **تحديث معتمد:** العلامة الأساسية أصبحت `comm.ly` (الموقع الأساسي/المنتج/الحساب)، والنطاقات (3 / 4 / 6 / 7 / 8 / 9 .com.ly) محركات تابعة للشبكة تعمل بنفس المحرك وقاعدة البيانات، ويمكن إضافة أي نطاق جديد لاحقاً دون التأثير على الموقع الأساسي.
> البنية المجانية بالكامل على Cloudflare: مشروع Pages لكل نطاق من نفس المستودع.

---

## 1. البنية المقترحة

```
GitHub Repository (واحد)
│
├── sites/registry.mjs        ← إعداد الستة مواقع (هوية، ألوان، نصوص AR/EN، دومين)
├── build/build.mjs           ← يولّد dist/ لكل موقع: صفحات AR + EN + sitemap + robots
├── templates/                ← قوالب HTML (هبوط، خصوصية، شروط، اتصال، شبكة، لوحة تحكم)
├── engine/functions/         ← Cloudflare Pages Functions (المحرك المشترك)
│     ├── _middleware.js      ← الموجّه: API + تحويل الروابط + Admin
│     ├── _lib/               ← التحقق، التوليد، قاعدة البيانات، المصادقة
│     └── schema.sql          ← جداول D1
├── public/assets/            ← CSS/JS/شعارات SVG (تُنسخ لكل موقع)
├── .github/workflows/        ← نشر تلقائي: 6 مشاريع Pages بمصفوفة واحدة
└── docs/                     ← أدلة النشر والمتطلبات
│
└── Cloudflare
      ├── Pages (6 مشاريع من نفس المستودع، كل مشروع SITE_ID مختلف)
      │     ├── 3.com.ly  ──┐
      │     ├── 4.com.ly    │
      │     ├── 6.com.ly    ├── نفس المحرك → نفس D1
      │     ├── 7.com.ly    │   (شبكة موحّدة: الرابط يعمل على الستة)
      │     ├── 8.com.ly    │
      │     └── 9.com.ly  ──┘
      ├── D1  ← جدول links + clicks + daily_stats (مجاني)
      └── KV  ← كاش التحويلات + حدود المعدل (مجاني)
```

## 2. نموذج عمل المحرك

| المسار | الوظيفة |
|---|---|
| `POST /api/shorten` | إنشاء رابط (URL، كود مخصص، مدة انتهاء) + فحص أمان |
| `GET /:code` | تحويل 302 على حافة الشبكة + تسجيل النقرة |
| `GET /api/stats` | إحصاءات (محمية برمز إداري) |
| `POST /api/admin/login` | دخول لوحة التحكم (كلمة مرور مشفّرة بـ HMAC) |
| `GET /:code+` (اختياري) | صفحة معاينة قبل التحويل |

**ميزة الشبكة الموحّدة:** أي رابط يُنشأ على 3.com.ly يعمل تلقائياً على 4 · 6 · 7 · 8 · 9 لأن جميعها تقرأ من نفس جدول D1. وكل رابط يُسجّل النطاق الذي جاءت منه النقرة (host) لأغراض الإحصاء.

> الأرقام قد تتغير من Cloudflare؛ تظهر الحدود الفعلية في لوحة التحكم عند إنشاء كل مورد.

### ما لا نحتاجه (توفير)
- ❌ خادم VPS — لا.
- ❌ قاعدة بيانات خارجية (Supabase/PlanetScale) — لا، D1 كافية.
- ❌ Vercel Pro أو أي استضافة مدفوعة — لا.
- ❌ شهادات SSL — Cloudflare يمّنحها تلقائياً.

## 4. المتطلبات من صاحب المشروع

1. **Cloudflare Account ID + API Token** بصلاحيات: `Pages:Edit`، `D1:Edit`، `KV:Edit` (لأنشر أنا المواقع والموارد مباشرة).
2. **مستودع GitHub** فارغ أنشئه (أو أُنشئ أنا المجلد وأعطيك أوامر الدفع).
3. **عنوان بريد الاتصال** لكل موقع أو بريد موحّد (مثلاً `hello@com.ly`).
4. **تأكيد هوية العلامات**: الافتراضي الآن = أرقام الدومينات + شعار هندسي مستقل لكل رقم + مظلة «Comly Network».
5. (اختياري) كلمة مرور لوحة التحكم الإدارية — تُخزّن كـ Secret في Cloudflare ولا تُرفع للمستودع.

## 5. خطة SEO المجمّعة (الهدف: سلطة واحدة من ستة نطاقات)

- **محتوى فريد لكل موقع** لا مجرد نسخ: نبرة مختلفة، أمثلة مختلفة، صفحة «الشبكة» خاصة بكل موقع.
- **hreflang** ar/en + canonical لكل دومين (لا محتوى مكرر بين النطاقات).
- **sitemap.xml + robots.txt** يولّدان تلقائياً لكل دومين على حدة.
- **ربط تبادلي**: كل موقع يذكر الخمسة الآخرين في التذييل + صفحة شبكة + مقال مشترك موقّع بكل نطاق.
- **بيانات منظمة JSON-LD**: Organization + WebSite + FAQPage + BreadcrumbList.
- **Google Search Console**: إضافة الستة نطاقات + إرسال الخرائط.
- **سلطة النطاق**: النطاقات الستة تعمل كتعدد حقيقي للبنية التحتية (احتياطي عند حجب دومين أو تعطله).

## 7. طبقة الخدمة المخصصة لاحقاً (بدون كسر المجانية)

- **White-label domains**: Cloudflare for SaaS — يسمح للعميل بربط نطاقه الخاص؛ له حد مجاني ثم رسوم لكل نطاق.
- **API Keys** و**حدود استخدام** لكل عميل: تُضاف كجدول في نفس D1.
- **Stripe**: لتحصيل الاشتراكات (نسبة لكل عملية، لا اشتراك شهري علينا).
- **صفحات Link-in-Bio للعملاء**: تُبنى بطبقة إضافية على نفس المحرك (نمط Linktree مثل الذي في النموذج).
